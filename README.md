# matenOS 技术文档

matenOS 是一个从零实现的 32 位 x86 裸机操作系统。它不依赖 Linux、Windows、GRUB 或任何现成内核，而是由 512 字节的 BIOS 引导扇区把 C 内核读入内存，切换到 32 位保护模式，然后运行自带的中断、驱动、图形界面和应用程序。

系统启动后先显示 `hello,matenOS!`，随后进入 640×480×32 位色的图形桌面（UI 以 640×480 逻辑分辨率绘制，再 2× 放大）。桌面提供计算器、计时器、画图、记事本、文件管理器、机器码工作室、扫雷、贪吃蛇、设置、纸牌和蜘蛛纸牌二十二个应用（桌面分两页）。


![matenOS 启动画面](docs/boot.png)

## 一、项目定位

这个项目的目标不是做一个“能打印一行字”的演示，而是把一台小机器从加电到交互的完整链路走通：

- 固件把第一个扇区加载到 `0x7C00`
- 自己写引导代码，读磁盘、开 A20、建 GDT、进保护模式
- 自己写 C 内核入口，清 BSS、设栈、调 `kmain`
- 自己写 IDT、异常入口、PIC、PIT、键盘和鼠标驱动
- 自己写 VBE 图形初始化、帧缓冲绘制、字体渲染和窗口管理
- 自己写 RAM 文件系统、文本编辑器、画图程序和两个小游戏
- 自己写一个 x86 机器码子集解释器，让用户输入十六进制字节并运行

它适合用来学习操作系统启动流程、保护模式、中断控制器、PS/2 设备、VBE 图形和简单的文件系统设计。代码量不大，但每一层都能对应到真实硬件或真实协议，而不是纯应用层模拟。

## 二、快速开始

### 2.1 一键启动

在 Windows 下直接双击：

```text
启动matenOS.bat
```

脚本会做四件事：

1. 切换到脚本所在目录，避免相对路径错误
2. 在 `C:\Program Files\qemu`、`C:\Program Files (x86)\qemu` 和 `PATH` 中查找 `qemu-system-i386.exe`
3. 如果 `build\matenos.img` 不存在，自动调用 `build.ps1` 构建
4. 用 32 MB 内存、`-vga std` 和软盘启动方式启动 QEMU

如果 QEMU 没有安装，脚本会给出提示并暂停，不会一闪而过。

### 2.2 PowerShell 启动

```powershell
powershell -ExecutionPolicy Bypass -File .\run.ps1
```

启动光盘版：

```powershell
powershell -ExecutionPolicy Bypass -File .\run.ps1 -Iso
```

### 2.3 直接调用 QEMU

软盘镜像：

```powershell
& 'C:\Program Files\qemu\qemu-system-i386.exe' `
  -fda .\build\matenos.img `
  -m 32 `
  -boot a `
  -vga std
```

ISO：

```powershell
& 'C:\Program Files\qemu\qemu-system-i386.exe' `
  -cdrom .\build\matenos.iso `
  -m 32 `
  -boot d `
  -vga std
```

### 2.4 串口日志

启动脚本会把 COM1 输出写到 `build\serial.log`。如果系统没有进入图形界面，先看这个文件：

```text
matenOS 0.1 booting
[ ok ] GUI initialized
```

如果连第一行都没有，说明问题在引导扇区、磁盘读取或保护模式切换；如果能进入 GUI，日志通常会停在 `GUI initialized`。

### 2.5 鼠标抓取

QEMU 默认使用相对坐标 PS/2 鼠标。窗口刚打开时，先点击一下画面，QEMU 会抓取鼠标；按 `Ctrl+Alt+G` 可以把鼠标释放回 Windows。全屏切换是 `Ctrl+Alt+F`。

## 四、应用程序详解

### 4.1 计算器

计算器使用 `int` 保存累加值和当前值，支持加、减、乘、除、等号和清零。它没有浮点数和括号，属于整数计算器。

- 鼠标点击按钮
- 键盘输入数字、`+ - * /`、`=`、`C`
- 除数为零时显示 `Error`
- 输入长度有限制，超过后忽略新的数字

计算器是验证 GUI 事件分发的最小应用：鼠标坐标命中按钮矩形，按下时执行对应操作，然后整屏重绘。

### 4.2 计时器

计时器是一个百分之一秒精度的秒表。它不使用 RTC，而是读取 PIT 的 tick 计数：

- PIT 频率 100 Hz，所以 1 tick = 10 ms
- 显示格式 `MM:SS.cc`
- `Start` 记录起始 tick
- `Stop` 冻结已用 tick
- `Reset` 清零
- 键盘空格也可以开始/暂停

因为显示到百分之一秒，运行状态下每 10 ms 会重绘一次窗口。QEMU 下这个刷新率没有问题；如果在真实老机器上觉得卡，可以降低刷新频率或只重绘数字区域。

### 4.3 画图

画图是这次重点增强的应用。画布大小约为 536×280 像素，使用 8 色调色板。打开后按数字键选择工具：

```text
1 画笔    2 直线    3 矩形
4 椭圆    5 填充    6 橡皮
```

操作方式：

- 画笔和橡皮：按住左键拖动，连续落笔
- 直线、矩形、椭圆：按下起点，拖动，松开时一次性绘制
- 填充：点击封闭区域，从点击点开始洪泛填充
- 橡皮：用背景色（浅灰）覆盖像素

画布内容保存在一个 `uint8_t` 数组里，每个像素保存调色板索引。每次重绘时，把画布逐像素转换成 32 位颜色写入后台缓冲区。这种设计的优点是简单、可撤销整屏重绘；缺点是每次重绘要遍历约 15 万个像素，画笔快速拖动时会有一定 CPU 开销。

形状工具目前采用“松开后落笔”，拖动过程中不显示预览。这样不需要额外的临时画布，也不会出现预览残影；代价是用户拖动时看不到最终形状，只能看到鼠标位置。


### 4.4 记事本

记事本用于编辑 RAM 文件系统中的文本文件。它支持：

- 可打印字符输入
- 回车换行
- 退格删除
- `Save` 保存到当前文件
- `New` 清空缓冲区

文本按 8×8 字体逐字符绘制，每行最多 66 个字符，超出自动换行。光标固定在文本末尾，暂不支持方向键移动和任意位置插入。对于 2 KB 以内的笔记，这个编辑器已经够用。

从文件管理器打开 `.txt` 文件时，会把文件内容读入记事本；保存时写回同一个卷和同一个文件名。

### 4.5 文件管理器

文件管理器有两个卷：

- `SYSTEM`：系统卷，用于放 readme、notes 等文件
- `DISC`：光盘卷，用于演示光盘读写

两个卷都支持：

- 浏览文件列表和大小
- 打开文件（文本进记事本，`.bin` 进机器码工作室）
- 新建文件
- 删除文件
- `Move >` 移动到另一个卷

文件系统的实现是纯内存的：

```c
#define FS_VOLUMES   2
#define FS_MAX_FILES 12
#define FS_MAX_NAME  20
#define FS_MAX_DATA  2048
```

每个卷最多 12 个文件，每个文件最多 2 KB 数据，文件名最长 19 个字符。删除文件时把后面的目录项前移，保持数组紧凑。移动文件时先复制到目标卷，确认复制成功后再删除源文件，避免目标卷满时把源文件弄丢。


### 4.6 机器码工作室

机器码工作室允许用户直接输入十六进制字节，然后运行。它不是把字节直接跳到内核里执行，而是通过一个 x86 子集解释器逐条解码执行，因此错误机器码最多得到 `bad opcode`，不会破坏内核。

界面左侧是十六进制编辑区，每行 12 个字节；右侧是输出和寄存器。按钮：

- `Run`：执行
- `Clear`：清空代码和输出
- `Demo`：载入示例
- `Save`：保存为 `program.bin`

示例程序输出 `Hi!`：

```text
B8 48 00 00 00 CD 20
B8 69 00 00 00 CD 20
B8 21 00 00 00 CD 20
B8 0A 00 00 00 CD 20
F4
```

支持的指令子集：

| 字节 | 指令 | 说明 |
| --- | --- | --- |
| `B8`–`BF` | `mov r32, imm32` | 装入 32 位立即数 |
| `40`–`47` | `inc r32` | 自增 |
| `48`–`4F` | `dec r32` | 自减 |
| `89 /r` | `mov r/m32, r32` | 仅寄存器模式 |
| `8B /r` | `mov r32, r/m32` | 仅寄存器模式 |
| `31 /r` | `xor r/m32, r32` | 异或 |
| `01 /r` | `add r/m32, r32` | 加 |
| `29 /r` | `sub r/m32, r32` | 减 |
| `83 /0` | `add r/m32, imm8` | 立即数加 |
| `83 /5` | `sub r/m32, imm8` | 立即数减 |
| `83 /7` | `cmp r/m32, imm8` | 比较 |
| `3D` | `cmp eax, imm32` | EAX 比较 |
| `74` / `75` | `jz` / `jnz rel8` | 条件跳转 |
| `EB` | `jmp rel8` | 短跳转 |
| `E9` | `jmp rel32` | 近跳转 |
| `90` | `nop` | 空操作 |
| `CD` | `int imm8` | 自定义系统调用 |
| `F4` / `C3` | `hlt` / `ret` | 停止 |

自定义中断：

- `INT 20`：把 AL 当作 ASCII 字符输出
- `INT 21`：输出 EAX 的十进制
- `INT 22`：换行
- `INT 23`：输出 EAX 的十六进制

解释器最多执行 100000 步，防止死循环卡死 GUI。寄存器窗口显示 EAX、ECX、EDX、EBX、EIP。


### 4.7 扫雷

扫雷使用 10×10 网格，12 颗雷：

- 左键翻开格子
- 右键插旗/取消旗
- 数字表示周围八格中的雷数
- 翻开所有非雷格获胜
- 踩雷失败
- 顶部 `Reset` 重新开局

翻开使用栈式洪泛算法：如果格子周围没有雷，就继续展开相邻格。旗子格不会被洪泛打开。这个实现没有“第一次点击必安全”的保护，第一下仍可能踩雷。


### 4.8 贪吃蛇

贪吃蛇使用 20×12 网格，每 12 个 PIT tick（约 120 ms）移动一格：

- `W/A/S/D` 控制方向
- `R` 重新开始
- 吃到红色食物加一分并变长
- 撞墙或撞到自己结束
- 结束后显示 `GAME OVER`

蛇身用固定数组保存坐标，长度上限 240。方向切换时禁止 180 度反向，避免立即撞到自己。

### 4.9 设置

设置应用用于调整鼠标体验：

- **Mouse speed**：1–5，默认 3。鼠标驱动会把 PS/2 的相对位移乘以这个值再除以 3，并用余数累加，避免慢速时丢小位移。
- **Cursor size**：1x 或 2x。2x 时光标按 24×24 绘制，命中点仍在左上角。
- **Theme**：Sea / Forest / Amber 三套桌面和标题栏配色。
- **Invert Y**：Normal / Invert，反转鼠标 Y 轴。
- **Reset**：恢复速度 3、光标 1x、主题 Sea、Y 轴 Normal。
- 键盘 `+` / `-` 调速度，`R` 重置。
- 点击 `License` 按钮或右上角箭头进入第二页，显示 The Unlicense；第二页右上角返回箭头回到设置页。

设置只保存在 RAM 中，重启后恢复默认。调整速度、光标大小或主题后，界面会立即按新值重绘。

### 4.10 纸牌

纸牌是简化版 Klondike：

- 7 列牌堆，4 个基础堆
- 点击牌堆中的牌选中，再点击目标列或基础堆移动
- 列内按红黑交替、点数递减排列；空列只放 K
- 基础堆按同花色 A 到 K 递增
- 点击左上角牌堆发一张到废牌堆；牌堆空时点击回收
- 移动后自动翻开列顶的暗牌
- 顶部 New 重新发牌

交互是“点击选中、再点击目标”，不提供拖拽。

### 4.11 蜘蛛纸牌

蜘蛛纸牌使用 1 花色、10 列、104 张牌：

- 前 4 列 6 张，后 6 列 5 张，每列最后一张明牌
- 点击牌列选中一段递减序列，再点击目标列移动
- 目标列顶牌必须比选中序列首牌大 1，或目标列为空
- 左上角 Stock 一次发 10 张，每列一张
- 一列底部形成 K 到 A 的完整序列时自动移除，计入 Completed runs
- 完成 8 组即胜利
- 顶部 New 重新发牌

## 五、文件系统与“光盘”的边界

很多初学者会问：既然文件管理器里有 `DISC`，是不是真的在读光盘、写光盘？

答案是：**不是物理光盘**。

物理压制的 CD-ROM 是只读的。要向 CD-RW 写数据，需要：

- ATAPI/SCSI 命令集
- 光盘刻录命令（WRITE、SYNCHRONIZE CACHE 等）
- UDF 或 ISO9660 的可写扩展
- 对光盘会话、轨道、lead-in/lead-out 的处理

当前内核没有实现 ATAPI 驱动，也没有实现 ISO9660/UDF 写入，因此 `DISC` 被实现成一个 **RAM 可写镜像**，用来完整演示文件管理器的交互：

- 可以浏览“光盘”里的文件
- 可以把系统卷的文件移动过去
- 可以删除、修改光盘卷里的文件
- 重启后内容恢复初始状态

这是一种诚实的取舍：在没有网络栈、没有 ATAPI、没有持久化块设备的阶段，先把文件管理器的交互和文件系统 API 做对，比伪造一个“能刻盘”的按钮更有意义。

如果以后要接真实光盘，合理的路线是：

1. 写 PCI IDE/ATAPI 驱动，识别 ATAPI 设备
2. 读 ISO9660 目录树，支持 Rock Ridge/Joliet 可选
3. 对 CD-RW 使用 UDF 或 packet writing
4. 把 `DISC` 卷从 RAM 数组换成块设备后端

## 六、构建系统

### 6.1 依赖

- Dev-C++ 自带的 TDM-GCC 4.9.2（`gcc.exe`、`as.exe`、`ld.exe`、`objcopy.exe`）
- NASM 3.02（`nasm.exe`）
- Windows PowerShell 5.1
- 可选：VMware Workstation 自带的 `mkisofs.exe`，用于生成 ISO

脚本会自动在以下位置查找：

```text
C:\Program Files (x86)\Dev-Cpp\MinGW64\bin
C:\Users\<user>\AppData\Local\bin\NASM
```

也可以在 `PATH` 中提供。

### 6.2 构建命令

```powershell
powershell -ExecutionPolicy Bypass -File .\build.ps1
```

构建过程：

1. 用 `gcc -m32` 编译 `kernel/*.c`
2. 用 `as --32` 汇编 `entry.S` 和 `isr.S`
3. 用 `ld -m i386pe -T kernel.ld` 链接成 PE，再由 `objcopy -O binary --only-section=.text` 转成扁平二进制
4. 计算内核占用的扇区数
5. 用 NASM 汇编引导扇区，`-D KERNEL_SECTORS=<n>` 把扇区数打进引导代码
6. 拼出 1.44 MB 软盘镜像
7. 如果找到 `mkisofs`，生成 El Torito ISO

关键编译选项：

```text
-m32 -ffreestanding -fno-builtin -fno-leading-underscore
-fno-stack-protector -fno-pic -fno-asynchronous-unwind-tables
-fno-common -mno-sse -mno-mmx -mno-80387
-mpreferred-stack-boundary=2 -O2
```

`-fno-leading-underscore` 很关键：MinGW 默认会给 C 符号加前导下划线，而汇编里的 `isr0`、`idt_load`、`kmain` 没有下划线。加上这个选项后，C 和汇编才能正确链接。

### 6.3 产物

| 文件 | 说明 |
| --- | --- |
| `build\matenos.img` | 1.44 MB 软盘镜像 |
| `build\matenos.iso` | El Torito 启动 ISO |
| `build\boot.bin` | 512 字节引导扇区 |
| `build\boot.lst` | NASM 汇编清单 |
| `build\kernel.bin` | 内核扁平二进制 |
| `build\kernel.map` | 链接映射 |
| `build\serial.log` | QEMU 串口日志 |

### 6.4 常见构建问题

**找不到 gcc**

检查 Dev-C++ 是否安装，或修改 `build.ps1` 里的候选路径。

**PowerShell 禁止运行脚本**

使用：

```powershell
powershell -ExecutionPolicy Bypass -File .\build.ps1
```

**内核超过 64 KB**

当前内核约 34 KB。如果继续增加功能，注意引导扇区用 `ES:BX` 把内核读到 `0x10000`，最多只能覆盖 64 KB。超过后需要把加载地址改到 `0x20000` 或更高，并同步修改链接脚本和跳转地址。

## 七、启动流程

### 7.1 从加电到 0x7C00

BIOS 完成自检后，如果从软盘启动，会把第一个扇区（512 字节）读到物理地址 `0x7C00`，检查末尾的 `0x55AA`，然后跳到 `0x0000:0x7C00` 执行。

这个扇区不是带分区表的真正 MBR，而是软盘风格的分区引导记录（VBR）。它没有分区表，也不依赖活动分区标志。

### 7.2 引导扇区做了什么

`boot/boot.asm` 的顺序：

1. `cli`、清方向标志、设置段寄存器和栈
2. 保存 BIOS 传来的启动盘号
3. 复位磁盘
4. 用 CHS 逐扇区读取内核到 `0x1000:0000`（物理 `0x10000`）
5. 通过端口 `0x92` 打开 A20
6. 调用 BIOS `INT 10h AX=1130h BH=03h` 取得 8×8 字体，复制到 `0x8000`
7. 用 Bochs VBE 端口 `0x1CE/0x1CF` 设置 640×480×32 线性帧缓冲
8. 加载 GDT
9. 置 `CR0.PE`，远跳进入 32 位保护模式
10. 设置数据段和栈 `0x700000`，跳到 `0x10000`

磁盘读取使用 18 扇区/道、2 磁头、80 柱面的 1.44 MB 几何。代码里有一个容易忽略的细节：计算 CHS 时先用 `div` 得到扇区号存到 `BL`，再用 `div` 求柱面和磁头，最后把 `BL` 恢复回 `CL`。如果直接覆盖 `CL`，所有读取都会变成同一个扇区，内核只会加载第一扇区。

### 7.3 内核入口

`kernel/entry.S` 是 32 位入口：

- 关中断
- 清方向标志
- 设置栈顶 `0x700000`
- 把 `__bss_start` 到 `__bss_end` 清零
- 调用 `kmain()`
- 如果 `kmain` 返回，进入 `cli; hlt` 死循环

清 BSS 很重要，因为扁平二进制只包含 `.text` 和已初始化数据，`.bss` 不在文件里，必须由启动代码手动清零。

### 7.4 内核初始化顺序

`kmain()`：

1. 初始化 COM1 串口
2. 初始化图形（读取 VBE 参数，设置帧缓冲指针）
3. 初始化文件系统
4. 初始化 IDT
5. 重映射 PIC
6. 初始化 PIT
7. 初始化键盘
8. 初始化 PS/2 鼠标
9. 开中断
10. 显示启动画面，等待约 1.2 秒
11. 进入 GUI 主循环

## 八、内存布局

| 物理地址 | 用途 |
| --- | --- |
| `0x00007C00` | 引导扇区 |
| `0x00008000` | BIOS 8×8 字体（2048 字节） |
| `0x00010000` | 内核代码、只读数据和已初始化数据 |
| `0x00012xxx` | 内核 `.bss`（具体地址由链接器决定） |
| `0x00200000` | 图形后台缓冲区（640×480×4 = 1,228,800 字节） |
| `0x00700000` | 内核栈顶，向下增长 |
| `0x00FD000000` | Bochs/QEMU VBE 线性帧缓冲 |

后台缓冲区放在 `0x200000`，而不是放进 `.bss`，是为了避免 1.2 MB 的 BSS 把内核数据段推过 640 KB 传统内存边界，也避免与 VGA/ROM 空洞重叠。栈放在 `0x700000`，离后台缓冲区和内核都很远。

这些地址只在“无分页、平坦模型”下成立。如果以后开启分页，必须建立恒等映射或做虚拟地址到物理地址的转换，DMA 缓冲区也要使用物理地址。

## 九、内核架构

### 9.1 GDT 与保护模式

引导扇区安装的 GDT 有三个描述符：

- 空描述符
- `0x08`：ring 0 代码段，基址 0，4 GiB
- `0x10`：ring 0 数据段，基址 0，4 GiB

进入保护模式后，CS 为 `0x08`，DS/ES/FS/GS/SS 为 `0x10`。没有 TSS，没有 ring 3，也没有分页，所有代码都在 ring 0 运行。

### 9.2 IDT 与异常

内核安装 48 个中断门：

- 0–31：CPU 异常
- 32–47：8259A 的 IRQ0–IRQ15

`isr.S` 为每个向量生成一个入口。无错误码的异常先压入 0，再压入向量号；有错误码的异常只压入向量号，错误码由 CPU 压入。公共入口 `isr_common` 保存 `pusha` 和段寄存器，切换到内核数据段，调用 C 函数 `isr_handler()`，然后恢复现场并 `iret`。

C 侧的 `struct regs` 与栈布局一一对应。异常会进入 `panic()`，打印原因并停机；IRQ 会分发给定时器、键盘和鼠标。

### 9.3 8259A PIC

PIC 被重映射到 `0x20`–`0x2F`，避免与 CPU 异常向量冲突。主片 IRQ2 用于级联从片。当前放行的中断：

- IRQ0：PIT
- IRQ1：键盘
- IRQ2：级联
- IRQ12：PS/2 鼠标

中断处理结束后，从片 IRQ 先发 EOI 给从片，再发主片；主片 IRQ 只发主片。

### 9.4 PIT

PIT 通道 0 设置为模式 3，分频值：

```text
1193182 / 100 = 11931
```

所以每秒 100 次中断，`timer_ticks()` 返回开机以来的 tick 数。计时器、贪吃蛇和 GUI 的动画节奏都基于这个计数。

### 9.5 键盘

键盘使用 scancode set 1。IRQ1 读取端口 `0x60`，处理：

- 按下/释放
- 左右 Shift
- Caps Lock
- 数字、字母、符号
- 回车、退格、Tab、空格、Esc

键盘中断把字符放进环形缓冲区，GUI 主循环用 `keyboard_poll()` 非阻塞读取，所以不会因为等待按键卡住鼠标和动画。

### 9.6 鼠标

鼠标是 PS/2 兼容设备，接在辅助端口：

1. 向 `0x64` 写 `0xA8` 启用辅助端口
2. 读控制器配置字节，置位 IRQ12，清除辅助时钟禁止位
3. 向鼠标发送 `0xF6`（默认值）和 `0xF4`（开启数据上报）
4. IRQ12 每次读 3 字节：标志、DX、DY
5. 根据符号位和溢出位更新 `mouse_x/mouse_y`
6. 左键按下产生 `mouse_clicked`，右键按下产生 `mouse_right_clicked`

鼠标是相对坐标设备。QEMU 窗口需要先点击抓取，否则移动不会传给 guest。光标是 12×12 位图，每次重绘时直接画到后台缓冲区的最后。

### 9.7 图形

图形使用 VBE 线性帧缓冲，物理模式 640×480×32，UI 逻辑分辨率 640×480，像素格式 `0x00RRGGBB`。后台缓冲区仍然只有 640×480×4 字节；`gfx_blit` 在输出时把每个逻辑像素放大成 2×2 物理像素，得到 640×480 的 4:3 画面，再居中放进 640×480 的 16:9 帧缓冲，左右各留 320 像素黑边。这样 QEMU 全屏到 16:9 显示器时只做等比缩放，不会把 UI 拉长或压扁。初始化通过 Bochs VBE 的 dispi 端口完成：

- 索引 `0x01`：X 分辨率
- `0x02`：Y 分辨率
- `0x03`：bpp
- `0x04`：enable
- `0x06`：虚拟宽度
- `0x08`/`0x09`：X/Y 偏移

设置完后，`0xFD000000` 是帧缓冲起始地址。绘制并不直接写显存，而是先写 `0x200000` 的后台缓冲区，最后 `gfx_blit()` 按行复制到显存。这样可以避免绘制过程中的撕裂，也让鼠标光标和窗口重绘逻辑更简单。

字体来自 BIOS 的 8×8 字模。引导阶段调用 `INT 10h AX=1130h BH=03h`，把 2048 字节复制到 `0x8000`，内核用 `font[(uint8_t)c * 8 + row]` 取字模，按位展开成像素。

### 9.8 GUI 主循环

GUI 是一个事件驱动循环：

1. 如果有鼠标移动，标记重绘
2. 如果有左键点击，命中图标/按钮/画布
3. 如果有右键点击，交给扫雷插旗
4. 如果当前是计时器，强制重绘
5. 如果当前是贪吃蛇，推进游戏
6. 读取键盘缓冲区，分发给当前应用
7. 如果 dirty，重绘整个桌面/窗口并 blit
8. `hlt` 等待下一次中断

因为没有窗口拖动和多窗口，命中测试很简单：先判断关闭按钮，再判断当前应用的控件。所有应用共享一个 560×388 的模态窗口，内容区为 536×338。

## 十一、调试与验证

### 11.1 串口

最简单的调试手段是串口。`serial_write()` 直接轮询 COM1 的发送寄存器，不依赖中断。QEMU 用：

```text
-serial file:build/serial.log
```

把输出写到文件。引导阶段、`kmain`、图形初始化和 GUI 初始化都有日志点。

### 11.2 QEMU 截图

无头模式下用 QMP 截图：

```python
screendump C:/path/screen.ppm
```

然后转换成 PNG 查看。开发过程中用这个方式验证了：

- 引导扇区进入保护模式
- 640×480 图形模式，640×480 逻辑 UI
- 桌面和图标
- 计算器 `7 + 8 = 15`
- 扫雷窗口
- 画图直线工具
- 机器码示例输出 `Hi!`
- 文件从 SYSTEM 移动到 DISC

### 11.3 常见故障

**黑屏，串口没有输出**

引导扇区没有执行。检查镜像是否 512 字节、末尾是否 `0x55AA`、QEMU 是否用 `-fda` 和 `-boot a`。

**串口停在 video 初始化**

VBE 模式设置失败。确认 QEMU 使用 `-vga std` 和至少 32 MB 内存。当前图形初始化只接受 32 bpp；如果 bpp 不是 32，`gfx_ready` 为 0，内核会停机。

**能进桌面但鼠标不动**

QEMU 没有抓取鼠标。点击画面，或检查 PS/2 鼠标初始化是否成功。IRQ12 必须放行，PIC 从片不能全部屏蔽。

**构建报 undefined reference**

检查 `-fno-leading-underscore` 是否生效，以及 `entry.S`/`isr.S` 是否参与链接。

**ISO 启动不了**

当前 ISO 使用 El Torito 软盘仿真，依赖 BIOS/CSM。纯 UEFI 固件不会识别。

## 十二、已知限制

- 仅支持传统 BIOS/CSM，不支持纯 UEFI
- 仅支持 QEMU/Bochs VBE dispi，未适配 VMware SVGA 或真实显卡的 VBE 路径
- 文件系统和 DISC 卷都在 RAM，重启丢失
- 没有 ATAPI/ISO9660 驱动，不能读写真实光盘
- 没有分页、用户态、多任务、SMP
- 没有网络栈，不能做 NTP/DHCP/DNS
- GUI 是单窗口模态，不支持多窗口拖动和层叠
- 记事本光标固定在末尾，不支持方向键和任意插入
- 画图没有保存/打开图片功能
- 计算器只有 32 位整数，没有小数和括号
- 扫雷没有第一次点击保护

## 十三、后续路线

如果继续开发，优先级建议如下：

1. **持久化文件系统**：接 ATA PIO 或 virtio-blk，把 RAM 文件系统换成块设备
2. **网络栈**：RTL8139 + ARP/IP/UDP/DHCP/DNS，为 NTP 对时做准备
3. **UEFI 启动**：GOP 帧缓冲 + UEFI 文件协议，逐步摆脱 BIOS
4. **多窗口 GUI**：窗口结构体、Z 序、拖动、最小化
5. **分页和用户态**：建立虚拟内存，把应用放到 ring 3
6. **更好的编辑器**：方向键、插入/删除、文件另存为
7. **画图保存**：把画布编码成简单位图写入文件系统

## 十四、结语

matenOS 的代码量不大，但它把“固件 → 引导 → 保护模式 → 中断 → 驱动 → 图形 → 应用”这条链路完整地走了一遍。它没有隐藏任何一层：磁盘读取是手写的 CHS 循环，GDT 是手写的描述符，中断入口是汇编 stub，文件系统是手写的数组管理，机器码工作室甚至实现了自己的 x86 子集解释器。

这类项目的价值不在于功能数量，而在于每一行代码都能对应到真实硬件行为。你可以从 `boot.asm` 开始，沿着 `0x7C00 → 0x10000 → kmain → gui_run` 一路读下去，看到一台机器是如何从加电变成一个有鼠标、有窗口、能画画和玩游戏的小系统的。

如果只想快速体验，双击 `启动.bat`；如果想研究实现，从 `boot/boot.asm` 和 `kernel/kmain.c` 开始读。两者之间，就是这个项目全部的故事。
